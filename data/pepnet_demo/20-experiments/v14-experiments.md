## 四、核心分析

### 4.1 out_task_space_weight 为什么有效？

```protobuf
task_space_indicator_label: "is_click"
in_task_space_weight: 1
out_task_space_weight: 0.01
```

- **in_task_space**（`is_click=1`）：CVR 正常计算 loss
- **out_task_space**（`is_click=0`）：CVR 以 0.01 权重计算 loss

默认值为 0。设为 0.01 后，CVR tower 从非点击样本接收超弱监督的"不要预测转化"信号。非点击样本占 95%，乘以 0.01 后总梯度贡献约为点击样本的 `95% × 0.01 / 5% = 19%`。

### 4.2 与 ctr45 的差异

| 机制                     | ctr45 (CTR weight↑) | Config C (out_task_space↑) |
| :----------------------- | :------------------ | :------------------------- |
| CTR tower 梯度放大       | ✅ 直接             | ❌ 不变                    |
| CVR tower 从非点击样本学 | ❌ 不变             | ✅ **新信号源**            |
| CVR AUC 提升             | +0.04%              | **+0.39%**                 |

### 4.3 容量缩减为何失败

可能解释：

1. PLE expert sharing 需要足够维度承载跨任务信息
1. Tower 容量影响 gate 的裁决能力
1. 过拟合源头是缺失的 dropout，不是容量过剩

### 4.4 代码修复未部署的后果

本轮所有 dropout_ratio 均未生效。待验证方向：

| 方向                          | 需要什么        | 预期 |
| :---------------------------- | :-------------- | :--- |
| Dropout 0.3 on CVR tower      | 修复 + 重跑     | 中等 |
| Dropout + out_task_space 叠加 | 修复 + Config C | 高   |
| Dropout + 容量缩减            | 修复 + A        | 低   |

### 4.5 离线评估的指标覆盖 gap：需要纳入 user-level metrics

ctr45 的离线 AUC（impression 级）双涨，但线上 uv_ctr/uv_cvr 双跌，揭示了当前离线评估体系的核心缺陷：

| 维度       | 离线评估           | 线上 A/B                      | 是否对齐 |
| :--------- | :----------------- | :---------------------------- | :------: |
| 粒度       | impression 级      | impression + user 级          |    ❌    |
| 主要指标   | AUC                | pv_ctr/pv_cvr + uv_ctr/uv_cvr | 部分对齐 |
| 覆盖均匀性 | 不评估（等权样本） | 用户级指标反映分配公平性      |    ❌    |
| 长尾覆盖   | 不评估             | uv 指标直接衡量               |    ❌    |

**根因：** AUC 对每个 impression 等权计算，不区分该 impression 来自高频用户还是低频用户。当模型策略性地将曝光从低意向用户转移到高意向用户时，impression 级 AUC 可能保持或上升（因为转移后的 impression 排序更准），但 user 级指标（uv_ctr/uv_cvr）因为覆盖群体特征变化而下降。

**建议的改进方向：**

1. **离线加入 user-level metric 计算**：在 eval pipeline 中按 user 聚合，计算 user-weighted AUC 或 user-level BCE。TZRec 的 `grouped_auc` 按 `lifecycle_tags` 分组是类似思路，但粒度更细到 user 级别。
1. **样本级重加权**：对低频用户对应的 impression 在 loss 计算中施加更高权重，使模型优化目标与 user 级指标对齐。
1. **评估报告增加覆盖度指标**：如 unique users reached、per-user impression 分布的熵/基尼系数，用于检测曝光集中化趋势。
1. **Config C（out_task_space=0.01）的机制本身不放大 CTR 梯度**，因此不存在 ctr45 那种因权重放大导致的曝光策略偏移风险，推测其 uv 级指标偏离可能性较低。但 Config C 上线前仍建议在离线加入 user-level metric 验证。
