# T_max 修正实验 (GPU 数 / batch 效应)

> 验证: T_max / warmup 是**原始 step 数**, 不随 GPU 数自动缩放. 必须按 GPU 数 × per-GPU batch 重新计算.

## 背景: 之前 2 卡不提升 CVR 是假象

之前结论: "2 卡不提升 CVR, hash_fix 才是主因"
**真实原因**: 2 卡跑 epoch 1 用了 `T_max=73242` (2 卡的 step 数), 而 1 卡/4 卡实验错误用了同 T_max, 导致 **cosine 衰减比例严重失配**, LR 轨迹完全不同.

## 问题: T_max 未对齐导致 LR 轨迹不同

```python
T_max = 73242          # 固定 raw step 数
warmup_size = 2000     # raw step
num_epochs = 1
batch_size = 2048      # per-GPU
```

**实际 epoch 步数**:

- 1×A10: 1.5亿 / 2048 ≈ 73000 步 ≈ T_max → 衰减到 ~0%
- 2×A10: 1.5亿 / 4096 ≈ 36500 步 ≈ T_max/2 → 衰减到 ~50%
- 4×V100: 1.5亿 / 8192 ≈ 18300 步 ≈ T_max/4 → 衰减到 ~75%

**结论**: 同样的 T_max, 不同 GPU 数对应不同 cosine 衰减比例, LR 轨迹完全不同, **不可比较**.

## 修复: 对齐 cosine 衰减比例

| Config           | T_max  | 期望 epoch 步  | 实际比例 |
| :--------------- | :----: | :------------: | :------: |
| v6_baseline_1gpu | 140000 |  76000 (L20)   |   54%    |
| v6_baseline_2gpu | 73242  | 38285 (2×A10)  |   52%    |
| v6_baseline_4gpu | 37000  | 18300 (4×V100) |   49%    |

**目的**: 让所有 GPU 数在 epoch 结束时, LR 都衰减到 ~50% (cosine 中点).

## 实测结果 (2026-06-06, 修复前单跑)

| Config           | GPU    | T_max  | CVR AUC | 备注                                          |
| :--------------- | :----- | :----: | :-----: | :-------------------------------------------- |
| v6_baseline_2gpu | 2×A10  | 73242  | 0.7822  | ⏳ 基线 (待确定性重跑)                        |
| v6_baseline_1gpu | 1×L20  | 140000 | 0.7643  | ⏳ **-0.18pp** (L20 cc\<7.0 +1 GPU, 仍有差距) |
| v6_baseline_4gpu | 4×V100 | 37000  | 0.7569  | ⏳ **-0.25pp** (V100 16GB OOM 风险)           |

## 仍然存在的本质差异

1. **GPU 硬件**: A10 (sm_86) vs L20 vs V100 — 算法选择不同
1. **DDP bucket 状态**: 不同 GPU 数 = 不同 bucket 划分
1. **GPU 类型不可移植**: 即使 T_max 对齐, cvr 仍有 -0.18 ~ -0.25pp 差距

## 关键发现: 非单调 batch 效应, 2×A10 是甜区

| Eff Batch | GPU    |    CVR     | 备注                            |
| :-------: | :----- | :--------: | :------------------------------ |
|   2048    | 1×L20  |   0.7643   | L20 cc\<7.0, 仅做参考 ⏳ 待重跑 |
|   4096    | 2×A10  | **0.7822** | ⏳ 待确定性重跑                 |
|   8192    | 4×V100 |   0.7569   | V100 16GB OOM 风险 ⏳ 待重跑    |

**不是简单的 "batch 越大越好"**:

- 1×L20 (2048) → 0.7643 (L20 vs A10 有硬件差异, ⏳ 待重跑)
- 2×A10 (4096) → 0.7822 (修复前, ⏳ 待重跑)
- 4×V100 (8192) → 0.7569 (-0.25pp vs 2×A10, ⏳ 待重跑)
- ⚠️ **从未跑过 1×A10**, 无法区分"batch 2048 vs 4096"和"硬件差异"哪个是主因

**结论** (不变, 不受噪声影响): 2×A10 (eff_batch=4096) 是本项目固定训练配置, 部署时重新校准 T_max.

## 决策

- ✅ **固定 2×A10 (eff_batch=4096)** 作为生产训练配置
- ❌ 不再尝试 1 卡或 4 卡
- ⚠️ 部署时如换 GPU 集群, 必须重新校准 T_max
