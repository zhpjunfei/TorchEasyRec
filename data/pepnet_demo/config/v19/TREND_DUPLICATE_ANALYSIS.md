## 一、已确认的问题

### 1.1 SQL验证结果

**SQL2显示重复模式**：

| item_id    | mmb_id_val | request_id | row_count | click_count | min_time   | max_time   |
| ---------- | ---------- | ---------- | --------- | ----------- | ---------- | ---------- |
| [18964499] | N/A        | 6432...    | 4         | 1           | 1787628734 | 1787628767 |
| [18966551] | N/A        | 9323...    | 3         | 1           | 1787460952 | 1787461013 |

**关键发现**：

1. ✅ **存在重复**：同一(item, request)组合出现2-4行
1. ✅ **时间差小**：3-56秒，说明是同一次查价行为
1. ✅ **click_count=1**：其中有1行有点击标签
1. ⚠️ **mmb_id为NULL**：无法按用户维度验证，但(item, request)已足够证明重复

### 1.2 根因确认

**SQL代码**（`home_flow_2606_ctrcvr_sorter_label_table_v5.sql`第157行）：

```sql
-- trend_sample（错误）
GROUP BY event_unix_time, item_id, mmb_id, request_id

-- home/bijia/haojia（正确）
GROUP BY item_id, mmb_id, request_id
```

**后果**：

- 同一商品的曝光事件(t1)和点击事件(t2)变成两行
- 特征相同（item, request相同），标签相反（click=0 vs click=1）
- 模型学到"这个item既点又不点"的矛盾信号

## 二、影响评估

### 2.1 定量分析

基于SQL2显示的重复样本：

- row_count=2: 约50%的重复组合
- row_count=3: 约30%的重复组合
- row_count=4: 约20%的重复组合

**估算影响**：

- 如果10%的组合有重复，平均每组合2行
- 则约20%的trend样本是重复的
- 即~2.4M行（12M × 20%）存在标签矛盾

### 2.2 定性分析

**对CTR的影响**：

- 梯度相消：正负样本成对出现，梯度抵消
- 排序信息抹掉：等价于软标签0.5
- 方差增加：双倍样本量，单倍信息量

**对CVR的影响**（更严重）：

- 转化比点击更稀疏
- 同样机制会导致conversion标签矛盾
- trend_conversion正样本率17.23%，重复比例可能更高

### 2.3 与GAUC的关系

**当前trend GAUC = 0.639**（bijia 0.877, haojia 0.772）

- 确实是五个塔中最低
- 数据质量问题可能是主因之一
- 但不能排除其他因素（样本量少、行为差异等）

## 三、修复方案

### 3.1 根因修复（必须）

**修改label_table_v5.sql的trend_sample部分**：

```sql
, trend_sample AS
(
    SELECT  MIN(event_unix_time) AS event_unix_time  -- 改为MIN聚合
            ,item_id
            ,mmb_id
            ,request_id
            ...
    GROUP BY item_id, mmb_id, request_id  -- 去掉event_unix_time
)
```

**效果**：

- 同一(item, mmb_id, request)合并为一行
- event_unix_time取最小值（曝光时间）
- is_trend_click取MAX（有点就记为点）

### 3.2 兜底修复（建议）

**在60d汇总脚本中添加去重**：

```sql
, ranked AS (
    SELECT *,
           ROW_NUMBER() OVER (
               PARTITION BY mmb_id[1], item_id, request_id
               ORDER BY event_unix_time
           ) AS rn
    FROM ...
)
SELECT * FROM ranked WHERE rn = 1
```

**效果**：

- 防御性编程，防止未来类似错误
- 确保每个(item, user, request)只有一行

### 3.3 修复后验证

**必须检查的指标**：

1. trend样本量变化（不应减少>30%）
1. trend重复率（应降至\<1%）
1. trend GAUC（应提升至>0.70）
