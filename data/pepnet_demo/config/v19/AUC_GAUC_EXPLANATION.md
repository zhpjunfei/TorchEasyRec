# AUC < 0.5 但 GAUC > 0.75 的深度解析

**日期**: 2026-10-18
**场景**: bijia_click 辅助任务 (AUC=0.327, GAUC=0.872)

______________________________________________________________________

> **修订（2026-10-21）**：初版把 "AUC < 0.5" 归因为「校准差 / 正样本被系统性低估」，**这是错误的**。
> AUC = P(正分 > 负分) 对分数的任何严格单调变换（含加性偏移、Platt 缩放）都不变，校准不可能改变 AUC。
> 真实机制：池化配对池被越权样本污染——约 89.5% 的"负样本"来自任务空间之外（被 `is_bijia_scene` 掩码挡在 loss 之外、得分未受约束），详见 §4.1 修订版。
> 另：§4.2 / §5.3 的「加性偏移不改变相对顺序」论证本身正确，但同一论证对全局 AUC 同样成立，因此不能用来解释 AUC 与 GAUC 的差异。

## 一、核心结论

**AUC < 0.5 不代表模型坏了！**

关键在于区分两个指标的**配对池**：

- **AUC（池化）**: 全局配对比较——但配对池混入了任务空间之外的样本，口径失真
- **GAUC**: 任务空间内配对比较（本项目 `grouping_key: "is_bijia_scene"`），不被越权配对污染

（初版写"AUC 受校准影响大"——错误。校准是分数的单调变换，AUC 与 GAUC 都对它不变。）

## 二、概念澄清

### 2.1 AUC (Area Under ROC Curve)

**定义**: 随机抽取一个正样本和一个负样本，正样本得分 > 负样本得分的概率

**公式**:

```
AUC = P(score(pos) > score(neg))
```

**特点**:

- 全局指标，对所有样本计算
- 对分数的任何严格单调变换不变（**校准不影响 AUC**）
- 配对池里若混入任务空间之外的样本，数值会失真（见 §4.1）

### 2.2 GAUC (Grouped AUC)

**定义**: 先按用户分组计算 AUC，再按样本数加权平均

**公式**:

```
GAUC = Σ(N_u / N) * AUC_u
```

其中 `AUC_u` 是用户 u 内部的 AUC，`N_u` 是该用户样本数

**特点**:

- 分组指标，衡量用户内排序能力
- 不受全局校准影响
- 更贴近线上效果

## 四、机制解释

### 4.1 为什么 AUC < 0.5？（2026-10-21 修订）

> 初版写「全局校准差（正样本被系统性低估）」——**错误**。
> 校准是对分数做严格单调变换，而 AUC = P(正分 > 负分) 对单调变换不变，
> 因此"校准差"在数学上不可能让 AUC 从 0.5 掉到 0.32。以下是真实机制。

**原因**: 池化配对池被越权样本污染——89.5% 的"负样本"来自任务空间之外

bijia 塔配置了 `task_space_indicator_label: "is_bijia_scene"`（in=1 / out=0）：

```
正样本 217    = 比价点击行（任务空间内）
负样本 3,879  = 比价未点击 409（任务空间内，被训练"应得低分"）
              + 场景外 3,470（占 89.5%）← 标签硬编码 0，
                但被掩码挡在 loss 之外，从未被训练"应得低分"，
                得分是未受约束的外推值
```

**配对分解（v2 修复版 20261019 日志实测）**:

```
AUC_pool = π · AUC_内 + (1−π) · P(正分 > 场景外分)
0.316  = 0.105 × 0.877  +  0.895 × 0.250
```

即：真·比价点击行只赢过 25% 的场景外行；0.316 里**七成的"错误"来自场景外配对**。
模型在真正该管的场景内是 **0.877**。

**根本原因（订正）**:

1. 指标口径：池化 AUC 把任务空间之外的行也算作负样本（配对池污染）
1. 这些行的得分不受 loss 约束（掩码生效的必然副产品，不是模型 bug）
1. ~~正样本率低 / 缺乏校准层~~ ← 与 AUC < 0.5 无关；校准只影响绝对概率，不影响排序类指标

### 4.2 为什么 GAUC > 0.75？

**原因**: 用户内排序正确

```
对于每个用户 u：
  点击样本基础分数: N(0.07, 0.01)
  未点击样本基础分数: N(0.03, 0.01)

  全局偏移: -0.045 (加性，不影响相对顺序)

  最终：点击样本得分 > 未点击样本得分
  → 用户内 AUC 高
  → GAUC > 0.75
```

**关键洞察**: 全局偏移是加性的，不改变用户内相对顺序。
**但同一论证对全局 AUC 同样成立**——AUC 也只依赖成对相对顺序，加性偏移/单调变换都不改变它。
所以"AUC 低、GAUC 高"的差异**不能**用校准解释，只能用配对池构成解释：
GAUC 只在任务空间内配对，池化 AUC 混入了 89.5% 的场景外配对。

## 五、ROC 曲线分析

### 5.1 正负样本不均衡的影响

当正样本率 = 5% 时：

```
TPR (真正例率) = TP / P
               = TP / 22,335  ← 分母小，TPR 敏感

FPR (假正例率) = FP / N
               = FP / 421,021 ← 分母大，FPR 变化缓慢
```

**后果**:

- ROC 曲线 x 轴 (FPR) 变化缓慢
- ROC 曲线 y 轴 (TPR) 变化敏感
- 曲线形状畸变，AUC 计算不稳定

### 5.2 对比图

```
正常情况 (正负均衡):          不均衡情况 (5% 正样本):

TPR                           TPR
1.0 |    ****                 1.0 |    *
    |   *   *                   |   *
0.5 |  *     *                  0.5 |  *
    | *       *                 0.5 | *
0.0 +----------- FPR           0.0 +-------*-------- FPR
    0    0.5    1.0                 0   0.8   0.9  1.0

AUC ≈ 0.85                    AUC 计算不稳定
```

## 六、线上效果分析

### 6.1 线上排序逻辑

```python
# 获取用户 u 的候选 items
items = get_candidates(user_u)

# 计算每个 item 的预测分数
scores = model.predict(items)

# 按分数降序排列
sorted_items = sort_by_score(items, scores, descending=True)

# 返回 Top-K
return sorted_items[:K]
```

**关键**: 排序只看相对大小，不看绝对值！

### 6.2 为什么 GAUC 高 → 线上效果好？

以用户 u1 为例：

```
原始分数: [0.038, 0.052, 0.041, 0.035, ...]
排序后:   [0.052, 0.041, 0.038, 0.035, ...]
              ↑ 点击样本排第1

即使所有分数都偏低（校准差），
只要相对顺序正确，排序效果就好！
```

### 6.3 结论

| 指标        | 与线上效果的关系                             |
| ----------- | -------------------------------------------- |
| AUC（池化） | 弱相关（配对池混入任务空间外样本，口径失真） |
| **GAUC**    | **强相关（衡量任务空间内排序）**             |
| NDCG        | 强相关（直接衡量排序质量）                   |

**建议**: 以 GAUC 为主要评估指标，而非池化 AUC。

## 七、改进方案

### 7.1 立即执行（修正指标口径，2026-10-21 修订）

> 下列方案初版定位成"修复校准以提升 AUC"——**方向错误**，不建议照做：
> 校准无法改变 AUC（单调变换不变）；正样本加权 / Focal 会进一步扭曲概率，且对场景内排序未必有益。
>
> 真正该做的两件事：
> ① 辅助任务只读 `grouped_auc { grouping_key: "is_bijia_scene" }`（= 0.877），池化 AUC 从评估报告退役；
> ② 若下游需要绝对概率（出价/阈值/混排比例）再加校准层——它只影响绝对值，不要用它"修 AUC"。

**方案1: 提高正样本权重（不推荐，见上方说明）**

```protobuf
# 在 loss 计算时提高正样本权重
loss = -w_pos * y * log(p) - w_neg * (1-y) * log(1-p)
where w_pos = 5, w_neg = 1
```

**方案2: 使用 Focal Loss**

```python
# 聚焦于难分类样本
loss = -(1-p)^gamma * y * log(p)
where gamma = 2.0
```

**方案3: 添加校准层**

```python
# 在模型输出后加 Platt Scaling
 calibrated_score = 1 / (1 + exp(-(A * score + B)))
# 其中 A, B 通过验证集拟合
```

### 7.2 中期优化（增强区分度）

**方案4: 特征工程**

- 添加更多用户个性化特征
- 优化序列特征（click_50_seq, chajia_50_seq）
- 添加场景交叉特征

**方案5: 模型调整**

- 调整 AFP 温度参数，促进特征路由
- 增加 expert 数量
- 调整 task weight

### 7.3 长期规划（架构优化）

**方案6: 样本均衡**

- 过采样正样本
- 或欠采样负样本
- 或使用混合采样策略

**方案7: 多阶段训练**

- Stage 1: 预训练（使用全部数据）
- Stage 2: 微调（使用平衡数据）
- Stage 3: 校准（Platt Scaling）

## 八、总结

### 8.1 关键要点

1. **AUC < 0.5 ≠ 模型坏了**

   - 是配对池污染：89.5% 的负样本来自任务空间之外（得分是未受约束的外推值）
   - 场景内 AUC 0.877 才是这个塔的真实成绩
   - 只要在任务空间内使用该分数，不影响线上排序效果

1. **GAUC > 0.75 = 模型有效**

   - 用户内排序能力优秀
   - 线上效果有保障

1. **应该关注 GAUC，而非 AUC**

   - GAUC 更贴近线上效果
   - AUC 在样本不均衡时失真

## 附录：代码示例

### A.1 计算 AUC 和 GAUC

```python
from sklearn.metrics import roc_auc_score
import numpy as np

# 全局 AUC
global_auc = roc_auc_score(labels, scores)

# Grouped AUC
gauc_scores = []
gauc_weights = []
for user_id in unique_users:
    mask = user_ids == user_id
    if len(set(labels[mask])) < 2:
        continue
    u_auc = roc_auc_score(labels[mask], scores[mask])
    gauc_scores.append(u_auc)
    gauc_weights.append(mask.sum())

gauc = np.average(gauc_scores, weights=gauc_weights)
```
