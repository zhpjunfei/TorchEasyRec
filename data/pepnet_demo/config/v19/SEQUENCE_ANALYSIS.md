## 关键发现

### 1. trend 场景序列特征失效

- **问题**: click_10/click_50/conv_20 的 P50=P90=P99=1
- **含义**: 50% 以上用户的序列被截断到最小长度 1
- **原因**: trend 是查价页面，用户目的性强，浏览深度低
- **影响**:
  - DIN encoder 无法从序列中学习有效信号
  - 辅助任务 `trend_click` 的序列特征几乎无效
  - 但静态特征（chajia_50）仍然有效

**建议**:

- 方案 A: 剔除 trend 辅助任务（序列无效）
- 方案 B: 降低 trend 辅助任务权重（weight=0.1）
- 方案 C: 为 trend 场景设计专用的浅层序列模型

### 2. bijia 场景序列特征偏弱

- **问题**: click_10 的 P50=1，click_50 的 P50=1
- **含义**: 约 50% 用户的序列被截断
- **原因**: bijia 用户行为较少
- **影响**: 序列特征对 bijia 场景的贡献有限

**建议**:

- 继续使用，但关注实验效果
- 如果效果不佳，可以降低 bijia 辅助任务权重

### 3. home/haojia 序列特征正常

- click_10 和 click_50 基本满长度
- 序列特征可以提供有效信号
- 无需特殊处理

## 配置建议

基于序列特征质量分析，建议调整 v19 配置：

### 方案 A: 保守方案（推荐）

```protobuf
# 只保留序列正常的辅助任务
task_towers {
  tower_name: "bijia_click"
  label_name: "is_bijia_click"
  weight: 1.0
  task_space_indicator_label: "is_bijia_scene"
  # bijia 序列偏弱，但样本量足够，先观察
}

# 剔除 trend 辅助任务（序列完全失效）
# task_towers { tower_name: "trend_click", ... } 注释掉
```

### 方案 B: 激进方案

```protobuf
# 保留全部辅助任务，但降低 trend 权重
task_towers {
  tower_name: "bijia_click"
  weight: 1.0
}
task_towers {
  tower_name: "haojia_click"
  weight: 1.0
}
task_towers {
  tower_name: "trend_click"
  weight: 0.1  # 降低权重，因为序列无效
}
```

### 方案 C: 分阶段实验

1. 第一阶段: 只加 bijia 辅助任务（验证方法有效性）
1. 第二阶段: 加 bijia + haojia
1. 第三阶段: 考虑是否加 trend（根据实验结果决定）
