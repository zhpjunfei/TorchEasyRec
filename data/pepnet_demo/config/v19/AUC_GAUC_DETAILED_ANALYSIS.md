# AUC 与 GAUC 计算逻辑深度分析

**日期**: 2026-10-20
**场景**: bijia_click 辅助任务 (AUC=0.327, GAUC=0.872)

______________________________________________________________________

> **修订（2026-10-21）**：初版把 "AUC < 0.5" 归因为「受校准影响 / 校准差」，**这是错误的**。
> AUC 与 GAUC 都只依赖成对相对顺序，对分数的任何严格单调变换（含加性偏移）都不变，校准不可能改变 AUC。
> 真实机制：池化配对池被越权样本污染——约 89.5% 的"负样本"来自任务空间之外（被 `is_bijia_scene` 掩码挡在 loss 之外、得分是未受约束的外推值），详见 §1.4 / §3.1 修订版。
> §5.3 的「校准不变性证明」本身正确，但它对全局 AUC 同样成立——所以不能用来解释 AUC 与 GAUC 的差异。

## 一、AUC 的计算逻辑

### 1.1 定义

AUC (Area Under ROC Curve) 是 ROC 曲线下的面积。

**ROC 曲线**：

- 横轴：FPR (False Positive Rate) = FP / N
- 纵轴：TPR (True Positive Rate) = TP / P

### 1.2 计算步骤

```
Step 1: 将所有样本按预测分数降序排列
Step 2: 遍历每个阈值 t，计算对应的 (FPR(t), TPR(t))
Step 3: 连接所有点形成 ROC 曲线
Step 4: 计算曲线下面积（梯形法则）
```

### 1.3 统计意义

```
AUC = P(score(pos) > score(neg)) + 0.5 * P(score(pos) = score(neg))
```

即：随机抽取一个正样本和一个负样本，正样本得分大于负样本得分的概率。

### 1.4 与校准的关系（2026-10-21 修订：不受校准影响）

假设正负样本分数分布：

- 正样本：N(μ_pos, σ²_pos)
- 负样本：N(μ_neg, σ²_neg)

则：

```
AUC ≈ Φ((μ_pos - μ_neg) / √(σ²_pos + σ²_neg))
```

其中 Φ 是标准正态分布的 CDF。

**关键（订正）**：AUC 依赖 μ_pos - μ_neg，但**校准不改变这个式子的取值**。
校准是对分数做严格单调变换 f（Platt 是 logistic 单调映射），而
`AUC = P(f(s⁺) > f(s⁻)) = P(s⁺ > s⁻)` 对任何严格单调变换都不变。
μ_pos - μ_neg 反映的是**排序能力**；初版把它归因于"校准"属于概念混淆。

## 二、GAUC 的计算逻辑

### 2.1 定义

GAUC (Grouped AUC) 是按用户分组计算 AUC 的加权平均。

**公式**：

```
GAUC = Σ_u (N_u / N) * AUC_u
```

其中：

- N_u：用户 u 的样本数
- N：总样本数
- AUC_u：用户 u 内部的 AUC

### 2.2 计算步骤

```
Step 1: 按用户分组
Step 2: 在每个用户内部计算 AUC
Step 3: 按样本数加权平均
```

### 2.3 不受校准影响的证明

假设全局校准偏移：score' = score - c

对于用户 u 内部：

- 正样本新分数：score'\_pos = score_pos - c
- 负样本新分数：score'\_neg = score_neg - c

比较大小：

```
score'_pos > score'_neg
⇔ score_pos - c > score_neg - c
⇔ score_pos > score_neg
```

**结论**：加性偏移不改变相对顺序，所以 GAUC 不变。

## 三、为什么 AUC < 0.5 但 GAUC > 0.75？

### 3.1 机制解释

| 维度        | 计算方式           | 受校准影响 | 当前状态                               |
| ----------- | ------------------ | ---------- | -------------------------------------- |
| 全局 AUC    | 所有样本配对比较   | ❌ 不敏感  | 0.327 (< 0.5)：配对池含 89.5% 场景外行 |
| 场景内 GAUC | 任务空间内配对比较 | ❌ 不敏感  | 0.872：这才是真实成绩                  |

**注**：两者差异来自**配对池构成**，不是校准——AUC 与 GAUC 对单调变换都不变。
本项目 `grouped_auc` 的 `grouping_key` 是 `is_bijia_scene`（按场景分组），
下文沿用"用户内"的说法是通用 GAUC 的习惯表述，含义同"任务空间内"。

### 3.2 具体例子

假设 bijia 场景的样本分布：

- 总样本：443,356
- 正样本（点击）：22,335 (5.05%)
- 负样本（未点击）：421,021 (94.95%)

模型预测分布：

- 正样本分数：N(0.043, 0.012)
- 负样本分数：N(0.047, 0.011)

**全局 AUC 计算**：

```
μ_pos - μ_neg = 0.043 - 0.047 = -0.004 < 0
→ AUC < 0.5
```

**用户内 GAUC 计算**：

- 用户 u1：正样本基础分数 0.075，负样本 0.035
- 全局偏移 -0.045 后：正样本 0.030，负样本 0.035
- 但用户内正样本仍排在前 30%
- → AUC_u ≈ 0.85
- GAUC = 平均(AUC_u) ≈ 0.87

### 3.3 图解说明

```
全局视角（决定 AUC）：
───────────────────────────────────────
正样本分数分布:  N(0.043, 0.012)
负样本分数分布:  N(0.047, 0.011)

        正样本          负样本
      .-------.      .-------.
     /         \    /         \
    |           |  |           |
    |    0.043  |  |   0.047   |
     \         /    \         /
      '-------'      '-------'

   正样本均值 < 负样本均值
   → AUC < 0.5

用户内视角（决定 GAUC）：
───────────────────────────────────────
用户 u1 的样本：
  正样本：0.030 (排名 第5/20)
  负样本：0.025, 0.028, 0.032, ...

  正样本 > 大部分负样本
  → 用户内 AUC 高
  → GAUC > 0.75
```

## 四、对线上效果的影响

### 4.1 线上排序逻辑

```python
# 获取用户 u 的候选 items
items = get_candidates(user_u)

# 计算每个 item 的预测分数
scores = model.predict(items)

# 按分数降序排列（只看相对大小）
sorted_items = sort_by_score(items, scores, descending=True)

# 返回 Top-K
return sorted_items[:K]
```

**关键**：排序只看相对大小，不看绝对值！

### 4.2 指标与效果的关系

| 指标        | 与线上效果的关系 | 原因                               |
| ----------- | ---------------- | ---------------------------------- |
| AUC（池化） | 弱相关           | 配对池混入任务空间外样本，口径失真 |
| **GAUC**    | **强相关**       | 衡量任务空间内排序能力             |
| NDCG        | 强相关           | 直接衡量排序质量                   |

### 4.3 结论

- GAUC = 0.872 → 任务空间内排序优秀
- AUC = 0.327 → 指标口径失真（89.5% 的配对来自任务空间外，其得分是未受约束的外推值）
- **不需要优化池化 AUC；也不要用"修校准"去抬它**

## 五、数学推导细节

### 5.1 AUC 的配对解释

```
AUC = (1 / (P * N)) * Σ_i Σ_j I(score_i > score_j)
                    i∈pos  j∈neg

其中 I() 是指示函数，P 是正样本数，N 是负样本数。
```

### 5.2 GAUC 的加权公式

```
GAUC = Σ_u (N_u / N) * AUC_u
     = Σ_u (N_u / N) * (1 / (P_u * N_u)) * Σ_i Σ_j I(score_i > score_j)
     = Σ_u (1 / (N * P_u)) * Σ_i Σ_j I(score_i > score_j)

其中 P_u 是用户 u 的正样本数，N_u 是用户 u 的负样本数。
```

### 5.3 校准不变性证明

对于用户 u 内部：

```
AUC_u = (1 / (P_u * N_u)) * Σ_i Σ_j I(score_i - c > score_j - c)
     = (1 / (P_u * N_u)) * Σ_i Σ_j I(score_i > score_j)
     = AUC_u (原始)
```

**证毕**。

**注（2026-10-21）**：上述证明对**全局 AUC 同样成立**——AUC 也只依赖成对相对顺序，
加性偏移乃至任何严格单调变换都不改变它。因此"AUC\<0.5 但 GAUC>0.75"不能用校准解释，
只能用配对池构成解释：池化配对混入了任务空间之外的样本（见 §3.1 修订注）。

## 六、优化建议

### 6.1 不需要优化的方向

❌ **不要为了提升 AUC 而优化**

- 这是"指标游戏"，不提升实际效果
- 可能引入过拟合风险
- 增加训练复杂度

### 6.2 应该优化的方向

✅ **优化 GAUC（提升个性化排序）**

1. 增强序列特征（click_50_seq, chajia_50_seq）
1. 优化 AFP 路由（调整 temperature）
1. 添加更多用户个性化特征

✅ **验证辅助任务价值**

1. 创建 ablation 配置（无辅助任务）

## 七、总结

### 核心结论

1. **AUC < 0.5 不代表模型坏了**

   - 是配对池污染：89.5% 的"负样本"来自任务空间之外（得分是外推值）
   - 场景内 AUC 0.872 是真实成绩
   - 只要在任务空间内使用该分数，不影响线上排序效果

1. **GAUC > 0.75 说明模型有效**

   - 用户内排序能力优秀
   - 线上效果有保障

1. **不应该优化 AUC**

   - 这是指标游戏
   - 应该优化 GAUC
