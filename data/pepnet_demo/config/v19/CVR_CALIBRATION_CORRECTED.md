## 一、错误分析（原报告）

### 1.1 我的错误理解

**原分析**：

```
pred_cvr = 0.3095
actual_cvr = 0.1195
calibration_error = +19% ❌
```

**错误原因**：

- 将`probs_cvr`直接理解为"转化率预测"
- 忽略了CTCVR的乘积监督机制
- 未考虑ESMM分解不可辨识性

### 1.2 正确理解（用户纠正）

```protobuf
use_ctcvr_loss: true  # CVR tower自身loss被跳过
```

**实际机制**：

```python
# CTCVR损失计算
ctcvr_label = ctr_label * cvr_label  # 只有双正样本有监督
ctcvr_logit = ctr_logit + cvr_logit  # 对数空间相乘
loss = BCE(sigmoid(ctcvr_logit), ctcvr_label)
```

**关键洞察**：

- CVR tower不直接学习`P(conversion)`
- CVR tower学习的是一个"潜变量"，与CTR相乘后解释为转化率
- ESMM分解不可辨识：`ctr × cvr = 0.112` 可以拟合 `0.1195`，但无法唯一确定ctr和cvr各自的值

### 2.2 为什么`probs_cvr=0.31`不是转化率？

**数学解释**：

设真实转化率为`P(C|X) = 0.12`，CTCVR模型学习：

```
P(C|X) ≈ σ(ctr_logit) × σ(cvr_logit)
       ≈ 0.36 × 0.31
       ≈ 0.11 ✅
```

但单独看：

```
σ(cvr_logit) = 0.31 ≠ 0.12
```

**原因**：`cvr_logit`被优化为"与ctr相乘后拟合转化率"的值，而非"直接拟合转化率"的值。

**类比**：

- 就像`a × b = 12`，我们知道`a=0.36, b=0.31`，但不能说`b=12`
- CVR tower的值是"相对缩放因子"，不是绝对概率
