## 一、问题与先验

当前模型 5 个任务里，**38.4% 的梯度预算给了非 ctr 任务**（ctcvr 13.7% + bijia_click 13.7% + trend_cvr 6.8% + haojia_click 4.1%），但它们对 home 主指标（CTR）的净贡献**从未被消融验证**。

已有证据（GRAD_CONFLICT step=7600 收敛 EMA）：`ema cos(ctr, aux)` 全部落在 −0.008 ~ +0.064 的"独立"带——**不帮不害**。这是弱先验（头部口径），最终判据只认消融 AUC。

## 二、两臂定义（唯一变量 = 辅助塔）

| 臂                        | 配置                                                     | 任务                                                     | 数据         |
| ------------------------- | -------------------------------------------------------- | -------------------------------------------------------- | ------------ |
| **A 对照（全任务）**      | `home_flow_2608_v19_multiscene_v4_shared_item_id.config` | ctr + cvr(ESMM) + bijia_click + haojia_click + trend_cvr | 10.22 样本集 |
| **B 消融（仅 ctr+ESMM）** | `home_flow_2608_v19_multiscene_v5_ctr_esmm_only.config`  | ctr + cvr(ESMM)                                          | 同上         |

**A 的 10-24 跑数已有，B 起训后直接对比**；若担心跨 run 噪声，两臂同批重跑一遍更稳。

### 单变量核验（已通过）

| 项                            | v4                                          | v5                                            | 一致              |
| ----------------------------- | ------------------------------------------- | --------------------------------------------- | ----------------- |
| diff                          | —                                           | +3 行头注释 / −67 行（辅助段：注释 + 3 塔块） | ✅ 唯一差异       |
| ctr 塔                        | w=4.5, ind=is_home_scene, mlp=[512,256,128] | 逐字节相同                                    | ✅                |
| cvr 塔（ESMM）                | w=1.0, ind=is_home_scene                    | 逐字节相同                                    | ✅                |

**设计要点**：

- `label_fields` 故意保留全部 10 个标签——B 臂虽然只有 2 塔，数据读取、batch 构成、`LABEL_DIST` 输出与 A 完全一致，**LABEL_DIST 可作同数据流指纹**；
- `T_max=6541` 与 A 臂一致（尽管 10.22 样本实测 7600 步、最优值应为 6600——**本消融不动它**，保证与 A 已有跑数严格同调度；重调 T_max 留给之后的全局批次）。

## 三、读数口径与判定规则

### 主判据

**home `grouped_auc_ctr`**（train decay 值，10.22 同数据）：

```
Δ = A(全任务) − B(仅 ctr+ESMM)
```

| Δ                 | 判定                 | 处置                                                                                                     |
| ----------------- | -------------------- | -------------------------------------------------------------------------------------------------------- |
| **≥ +0.5pp**      | 辅助塔有净收益       | **留任（实证价值）**，可再试加权                                                                         |
| **≤ −0.5pp**      | 辅助塔有害（负迁移） | **删**（直接出 v6=现状 B 上线基线）                                                                      |
| **\|Δ\| < 0.5pp** | 单 run 不可判定      | ≥2 seed；仍平 → 结论"无净收益"，倾向**删**（省 24.7% 梯度预算与 PLE 容量），除非团队要保留场景塔分数出口 |

（阈值 ±0.5pp = DecayAUC 分辨率/跨 run 噪声带；沿用既定判定纪律。）

### 副判据（辅助读数，不单独定案）

- `grouped_auc_cvr`：辅助塔对 CVR 的迁移；
- `binary_cross_entropy_ctr / ctcvr`：**只做同臂内趋势比较**——B 的 `total_loss` 必然明显低于 A（少三项求和），这是预期不是异常；各塔分量两臂可比（每塔 loss 独立归一，权重不重标定）；
- `LABEL_DIST`：两臂逐字段应一致（同数据流确认）；
- `[GRAD_CONFLICT]`：B 臂只剩 `ctr_cvr` 一对（其余对自动消失），正常。

## 四、运行注意

1. **同 whl 起训**（含 `[DIST_ENV]` 启动日志更好——顺带补上 world_size 的硬证据）；
1. **不要与其他 job 并发抢资源**（10-24 的 v4b/v4 并发跑过，速度读数被互相干扰）；
1. B 臂监控输出预期：`[GRAD_CONFLICT]` 只有 `grad_cos_sim_ctr_cvr` 一项；
1. 若复用 A 的旧跑数做对照，注意 Δ < 0.5pp 时的 seed 噪声归因（必要时 A 也重跑一次）。

## 五、后续排队（本方案不做）

- **ESMM 权重定价**（威胁表 #5）：ctcvr 权重 1.0 → 0.5 → 0 的三臂，为"隐式拿 CTR 换 GMV"定价；
- 消融结论回填 `ctr_improvement_adversarial_review.md` 威胁表 #4 与 `p13_abc_readout.md` 结论 1。

## 五、多 seed 操作手册（2026-10-26 重写——初版前提错误，作废）

> **初版写"跑 N 次 = N 个 seed（训练无 seed 开关）"——错，撤回。** 实测：同配置重跑的 segments **16 位浮点逐位相同**（v5 三 run、v4 两 run 均如此）；根源是 `tzrec/__init__.py:65-73`——`TORCH_MANUAL_SEED` **默认 42**、`USE_DETERMINISTIC_ALGORITHMS` **默认 1**，整个训练栈固定种子 + 确定性算法。**重跑 = 复制品，不产生新样本。**

### 1. 正确的 seed 开关（环境变量，零代码）

```bash
export TORCH_MANUAL_SEED=43        # 换种子即换一次独立 run；默认 42
export NUMPY_MANUAL_SEED=43        # 建议同步（默认也是 42）
```

在起训脚本/DLC 任务的环境变量里设置即可；`model_dir` 带 seed 后缀（如 `.../v5_seed43`）。

### 2. 运行矩阵（正式多 seed，可选）

| run      | 配置                      | 环境变量                    |
| -------- | ------------------------- | --------------------------- |
| 已有     | v4 / v5 各 1（= seed 42） | 默认                        |
| 新增 1/2 | `v4_shared_item_id`       | `TORCH_MANUAL_SEED=43 / 44` |
| 新增 3/4 | `v5_ctr_esmm_only`        | `TORCH_MANUAL_SEED=43 / 44` |

（若只做最小后手：两臂各 seed 43 一次，共 2 run，确认 Δ 符号稳定即可。）

### 3. 运行纪律

- 同一份样本快照（用 segments 样本数 + mean_target 作指纹对齐——**数据流漂移比任何实验效应都大**：曾观察到同配置跨流 trend GAUC 动 2.6pp）；
- 同 whl、同 launcher；model_dir 不覆盖；不并发抢资源；贴 `[DIST_ENV]` 行。

### 4. 收集与判定

每 run 收：`grouped_auc_ctr/cvr`、segments 两个 AUC、`bce_ctcvr/bce_ctr`、总步数。
判定（盯两个数）：**数 1** home GAUC 的 Δ 在种子间是否稳定（已知 seed42 下 Δ=+0.035pp，实用为零）；**数 2** `bce_ctcvr` 的 +0.5%（同流真实效应）是否稳定——两个数都稳 → **删 3 塔、v5 转正** 收卷。
