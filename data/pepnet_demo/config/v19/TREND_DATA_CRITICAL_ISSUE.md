## 二、问题本质

### 2.1 根因确认

```sql
-- trend_sample（错误）
GROUP BY event_unix_time, item_id, mmb_id, request_id

-- 正确写法（home/bijia/haojia）
GROUP BY item_id, mmb_id, request_id
```

**后果链**：

```
用户查价行为：
  t1时刻: trend_exposure → 行1: (item_X, req_Z, click=0)
  t2时刻: trend_click   → 行2: (item_X, req_Z, click=1)
  t3时刻: trend_conversion → 行3: (item_X, req_Z, click=1)

由于GROUP BY包含event_unix_time：
  → 三行不会被合并
  → 特征完全相同（item, request相同）
  → 标签相反（click=0 vs click=1）
  → 梯度相消，排序信息抹掉
```

### 2.2 对模型的影响

**理论分析**：

对于一对矛盾样本 (x, 0) 和 (x, 1)：

```
梯度1 = p - 0 = p
梯度2 = p - 1 = p - 1

净梯度 = p + (p - 1) = 2p - 1

当 p = 0.5 时：净梯度 = 0（完全抵消）
当 p ≠ 0.5 时：净梯度 ≠ 0（但仍向0.5方向拉）
```

**实际影响**：

1. **排序信号被抹掉**：等价于给该item打软标签0.5
1. **梯度方差增加**：双倍样本量，单倍信息量
1. **收敛变慢**：模型需要更多步数才能学到有效模式
1. **泛化能力下降**：学到的是"噪声平均"而非"真实信号"

## 四、优化方案

### 4.1 立即修复（P0）

**修改label_table_v5.sql**：

```sql
-- 修复前
, trend_sample AS
(
    SELECT  event_unix_time, item_id, mmb_id, request_id
            ...
    GROUP BY event_unix_time, item_id, mmb_id, request_id  -- ❌ 包含时间戳
)

-- 修复后
, trend_sample AS
(
    SELECT  MIN(event_unix_time) AS event_unix_time  -- ✅ 聚合时间戳
            ,item_id
            ,mmb_id
            ,request_id
            ...
    GROUP BY item_id, mmb_id, request_id  -- ✅ 去掉event_unix_time
)
```

**预期效果**：

- 重复率从37%降至\<1%
- 标签矛盾从98.5%降至\<5%
- trend GAUC预计提升至>0.70
- home CTR GAUC预计额外提升+0.5%~1%

### 4.2 防御性修复（P1）

**在60d汇总脚本中添加去重**：

```sql
, ranked AS (
    SELECT *,
           ROW_NUMBER() OVER (
               PARTITION BY item_id, request_id
               ORDER BY event_unix_time
           ) AS rn
    FROM ...
)
SELECT * FROM ranked WHERE rn = 1
```

**预期效果**：

- 即使未来SQL再次出错，数据管道也能兜底
- 确保每个(item, request)只有一行
