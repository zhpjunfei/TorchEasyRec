# 专利交底书

## 发明名称

**面向电商导购场景的商品帖子智能分发方法及系统**

## 技术领域

本发明涉及电子商务推荐系统领域，具体涉及一种面向电商导购场景的商品帖子智能分发方法及系统，尤其涉及新发布商品帖子的冷启动分发优化技术。

## 背景技术

### 现有技术方案

电商导购平台（如价格比较网站、商品内容社区）通常以"商品帖子"的形式向用户展示推荐内容。一套典型的推荐分发系统包含以下链路：

1. **召回层**：从海量商品库中召回候选帖子集合
1. **粗排层**：对召回结果进行初步筛选和排序
1. **精排层**：使用多任务深度学习模型（CTR/CVR预估）对候选帖子进行精确打分
1. **重排层**：结合业务规则（如多样性、新帖加权）对精排结果进行调整

其中，精排模型通常采用多任务学习架构（如MMoE、PLE、DCNv2等），同时对点击率（CTR）和转化率（CVR）进行联合预测，最终排序分数由两者的加权或非线性组合得到。

### 现有技术存在的问题

在实际运营中，新发布的商品帖子（"新帖"）面临显著的冷启动分发困难：

**问题一：新帖曝光严重不足**

在线上A/B测试数据中，新帖的曝光次数占比仅为16.88%，而老帖占83.12%；新帖的曝光UV占比为71.46%，意味着约28.5%的用户从未见过新帖（数据来源：2026年7月线上A/B测试，样本量约400万PV）。曝光不足直接导致新帖无法积累足够用户行为数据，形成恶性循环。

**问题二：服务端分配不均掩盖了模型侧潜力**

经深入根因分析发现，新帖分发少的核心原因并非模型排序能力差，而是服务端分配策略导致曝光不均衡。然而，精排模型对新帖的打分分布确实存在可优化空间——模型对新帖的CVR预估存在系统性偏差。

**问题三：对比学习中的品类跳跃问题**

当引入文本语义向量（title_vector）作为额外特征时，若将其直接放入主特征组参与排序，会导致跨品类的语义相似被错误关联（如将"舒适透气面料的卫衣"与"有机健康的食品"关联），产生品类跳跃的推荐结果。品类跳跃率定义为：推荐列表中，推荐商品的三级品类码与用户近15天交互品类码集合无交集的帖子占比。该方案虽能提升对比学习的效果，但引入了排序信号污染的风险。

**问题四：新帖样本稀缺导致训练不充分**

新帖样本在训练集中占比低（约17%），梯度贡献不足，模型难以学到稳健的新帖表示。同时，新帖的历史行为序列稀疏，DIN编码器的个性化信号不足。

### 相关技术文献

- 现有技术中，常见的新品冷启动方案包括：①简单的规则加权（如新帖Boost）；②数据层面的过采样；③辅助任务。但这些方案均存在明显局限：规则加权仅作用于重排阶段，无法提升模型本身对新帖的判别能力；过采样可能导致过拟合；辅助任务需要额外标注数据。

## 发明内容

### 要解决的技术问题

本发明旨在解决电商导购场景下商品帖子分发系统中新帖冷启动分发的技术难题，通过模型侧优化与数据管道优化的协同改进，提升新帖的曝光质量与分发效率。

### 发明构思

本发明的核心发明构思在于：**通过"梯度重塑"与"表示学习增强"两个维度的协同改进，系统性解决新帖冷启动的分发不公平问题。**

- **梯度重塑维度**：通过样本加权训练（层面一）和训练数据采样优化（层面四），从训练梯度的角度提升新帖的"学习优先级"，使模型在参数更新过程中更充分地吸收新帖的排序模式。
- **表示学习增强维度**：通过发布时间-品类组合特征建模（层面二）和对比学习的行为-语义对齐（层面三），从模型表示的角度提升新帖的特征表达质量和泛化能力。

两层维度的协同作用机制如下：梯度重塑确保模型"有机会学"新帖，表示学习增强确保模型"能学好"新帖；二者缺一不可——仅有梯度加权而无更好的表示能力，模型仍无法有效区分新帖的质量差异；仅有丰富的表示特征而无足够的梯度信号，模型因训练不充分而无法充分利用这些特征。

### 技术方案概述

本发明提出了一套分层递进的商品帖子智能分发技术方案，涵盖以下四个层面：

**层面一：基于发布时间粒度的样本加权训练**

在训练数据管道中，根据商品帖子的发布时间（`pub_hours`，即帖子发布至今的小时数）计算样本权重，对近期发布的帖子赋予更高的Loss权重，使模型在训练过程中更关注新帖的排序模式。

具体实现：将`pub_hours`划分为多个层级（Tier），不同层级对应不同的权重系数：

- Tier 0（\<0.5小时）：权重4.0×
- Tier 1（0.5~2小时）：权重2.0×
- Tier 2（2~24小时）：权重1.0×（默认）
- Tier 3（≥24小时）：权重0.6×

**层面二：基于组合特征的发布时间-品类交叉建模**

在SQL预处理阶段，将`pub_hours`与品类（`cate_id_path`）、价格标签（`price_tag`）、品牌（`brand`）进行组合，构建复合特征键。模型通过`id_feature`直接读取预计算的组合特征，绕过FG框架不支持链式引用的限制。

具体实现：`pub_hours`按业务语义分为5个桶（\<1h/1-6h/6-24h/24-72h/≥72h），与品类/价格/品牌拼接为复合key，通过ZCH（Zero Collision Hash，零碰撞哈希）机制处理在线 unseen 组合，该机制基于LFU/LRU淘汰策略管理hash bucket溢出，并通过动态阈值过滤函数对低频item进行兜底处理。

> **注**：层面一（4层级）与层面二（5桶）的分桶粒度不同，二者可协同使用或独立选用。层面一侧重于Loss加权训练，层面二侧重于特征表示增强。

**层面三：基于对比学习的行为-语义对齐**

构建双向对比学习目标，将用户行为序列编码向量（behavior_emb）与商品标题语义向量（title_vector）进行对齐：

- **View A（行为视角）**：通过DIN编码器从用户历史行为序列中聚合生成的目标物品行为向量
- **View B（语义视角）**：通过预训练文本编码器生成的商品标题128维语义向量

采用双向InfoNCE对比损失函数，分别计算行为到语义方向（v2t）和语义到行为方向（t2v）的损失，对正样本对施加吸引力，对难负样本（相似度最高的K个非正样本）施加排斥力。

关键设计：将`title_vector`置于独立的`contrastive`特征组，**不参与主排序塔的计算**，仅通过投影层参与对比学习，避免语义信号污染排序决策导致的品类跳跃问题。

**层面四：训练数据采样优化**

在SQL数据管道中对新帖样本进行复制up-sample，将训练集中新帖占比从约17%提升至约29%，使梯度对新帖的关注度提升约2倍，同时保持对老帖的学习覆盖。

### 有益效果

1. **新帖曝光UV占比提升**：通过模型评分优化+服务端重排加权的协同，预期新帖曝光UV占比从71.46%提升至85%以上
1. **新帖UVCTR提升**：预期从28.49%提升至35%以上
1. **模型侧贡献明确**：新帖独立AUC/Grouped AUC可作为模型优化的独立验证指标
1. **品类跳跃问题得到解决**：对比学习信号与排序信号解耦，保证推荐结果的品类一致性

## 具体实施方式

### 实施例一：系统整体架构

如图1所示，本发明的商品帖子智能分发系统包括：

**数据管道层**：

- 离线特征计算模块：基于MaxCompute/Hive进行批量特征计算
- 实时特征模块：基于Flink进行流式特征更新
- 样本生成模块：产出训练样本，包含`pub_hours`、`is_new_item`等元数据标签

**特征工程层**：

- 用户特征：用户画像、用户统计（15d/60d/360d）、KV统计（点击/转化/收藏）
- 商品特征：商品ID、品类路径、价格标签、品牌、发布时间
- 序列特征：点击序列、转化序列、收藏序列（支持DIN编码）
- 语义特征：商品标题向量（128维预训练向量，独立特征组）
- 组合特征：`pub_hours`×`cate_id_path`、`pub_hours`×`price_tag`、`pub_hours`×`brand`

**模型训练层**：

- 多任务排序模型：基于深度神经网络的多任务排序架构（如PEPNetDCNPLE等），同时对CTR和CVR进行联合预估
- 对比学习模块：InfoNCE损失，双视角对齐
- 样本加权模块：基于`pub_hours`层级的Loss加权
- 数据采样模块：新帖样本up-sample

**推理服务层**：

- 在线特征 computation（FG handler）
- 模型推理（GPU serving）
- 重排策略（新帖加权、多样性打散）

### 实施例二：多任务排序模型架构

多任务排序模型采用深度神经网络架构，包含以下核心子模块：

**1. 多特征分组嵌入**：

- `main_group`：主特征组（item_id、user特征、商品属性等）
- `cdot_group`：域特征组（请求域名、请求页面），用于slot级交互建模
- `bias_group`：偏置特征组（站点、层级、页面），提取首维1-dim偏置
- `lhuc_group`：门控特征组（站点、层级），用于参数个性化门控
- `contrastive_group`：对比学习特征组（标题语义向量），独立于主排序

**2. 特征交叉模块**：

- Slot级交互模块：对域特征进行动态压缩与交叉
- 显式特征交叉模块：对主特征进行多层交叉（低秩分解）
- 偏置提取：从各特征首维提取1-dim偏置向量并求和

**3. 个性化门控模块**：

- Embedding个性化门控：对主特征做元素级缩放
- 参数个性化门控：对深层MLP各层做scale-before-Dense门控

**4. 多任务共享层**：

- PLE（Progressive Layered Extraction）多层CGC路由，共享expert与task专属expert

**5. 任务塔**：

- CTR塔：MLP → 输出logit
- CVR塔：MLP → 输出logit
- Logit级融合：CVR logit = CVR塔输出 + CTR logit

### 实施例三：对比学习模块的详细实现

#### 3.1 数据流设计

```
用户行为序列 (click_50_seq, conversion_5_seq, ...)
    ↓
DIN Encoder (target attention over sequence)
    ↓
behavior_emb [B, DIN_out_dim]

商品标题向量 (title_vector)
    ↓
[contrastive] feature group（独立特征组，不参与主排序）
    ↓
title_vector [B, 128]
```

#### 3.2 对比学习损失函数

采用**双向InfoNCE对比损失**，包含两个方向：

**v2t方向（行为→语义）**：

```
对每个用户i：
  正样本：behavior_emb[i] ↔ title_vector[i]
  难负样本：从batch内选择相似度最高的K个非对角线元素
  sim[i,j] = (behavior_emb[i] · title_vector[j]) / τ_seq
  loss_v2t = -sim_c[i,i] + logsumexp(sim_hard_negative, dim=0)
```

其中：

- 温度τ为**per-seq_len自适应温度**（短序列噪声大→温度低→更确定）
- 正样本相似度经过**LogQ校正**：`sim_c = sim - log_q`，其中`log_q`为基于batch统计的热门度moving average，用于消除热门item偏差
- 仅对top-K+1相似度的难负样本计算loss，降低计算复杂度

**t2v方向（语义→行为）**：

```
对每个商品j：
  正样本：title_vector[j] ↔ behavior_emb[j]
  难负样本：从batch内选择相似度最高的K个非对角线元素
  sim[j,i] = (title_vector[j] · behavior_emb[i]) / τ_title
  loss_t2v = -sim[j,j] + logsumexp(sim_hard_negative, dim=0)
```

其中：

- 温度τ**固定为常数**（标题向量质量稳定，无需自适应）
- **不使用LogQ校正**：因为t2v方向的负样本是其他用户的行为向量，不携带item_id，不存在item频率偏差
- 两个方向均使用\*\*列方向（dim=0）\*\*的logsumexp，确保正确的负样本分布

#### 3.3 标题向量残差适配器

在双向对齐模式下，标题语义向量还经过一个残差式维度压缩-恢复网络（Title Adapter）：

```
t = t_raw + adapter(t_raw)
adapter = Sequential(
    Linear(128, 64),      # 128→64 维度压缩
    ReLU(),
    Linear(64, 128),      # 64→128 维度恢复
)
# 初始化策略：最后一层权重和偏置初始化为零
# 效果：训练初期退化为恒等映射，逐步学习语义适配变换
```

该适配器的零初始化设计确保对比学习初期不会对排序质量产生干扰，随训练推进逐步学习行为-语义空间的适配变换。

#### 3.4 特征组隔离设计

为解决品类跳跃问题，`title_vector`被放置在独立的`contrastive`特征组中，与主排序网络的`main`/`cross`/`cdot`/`bias`组物理隔离：

```protobuf
# 对比学习特征组（独立，不参与排序）
feature_groups {
    group_name: "contrastive"
    group_type: DEEP
    feature_names: "title_vector"
}

# 主排序特征组（不含title_vector）
feature_groups {
    group_name: "main"
    group_type: DEEP
    feature_names: "item_id" ... # 所有其他特征，不含title_vector
}
```

在模型forward pass中，`title_vector`仅通过投影层参与对比学习，**不影响排序score的计算**：

```python
# 排序部分（无title_vector）
deep_input = concat([LN(main), LN(cross), LN(cdot), LN(bias)])
ctr_logit, cvr_logit = shared_representation → task_towers(deep_input)

# 对比学习部分（独立路径）
behavior_emb = din_encoder(sequence_features)  # 来自主特征组
tv_group = grouped_features.get("contrastive")
title_vector = tv_group[:, :self._title_vector_dim]
v = self.contrastive_behavior_proj(behavior_emb)  # 投影对齐
t = title_vector + adapter(title_vector) if mode == "bidirectional" else title_vector
contrastive_loss = bidirectional_infonce(v, t, hard_k=K)
```

需要说明的是，`behavior_emb` 源自主网络的 DIN 编码器输出，其本身参与了主排序梯度的更新；标题语义向量通过独立的特征组定义，确保**标题向量本身不参与主排序网络的前向计算和梯度反向传播**，仅通过对比学习的共享DIN编码器间接影响行为向量的表示质量，实现了"对比学习优化表示质量，但不污染排序决策"的梯度隔离目标。

### 实施例四：pub_hours样本加权训练

#### 4.1 权重计算逻辑

在SQL数据管道中，根据`pub_hours`字段计算每个样本的`fresh_weight`：

```sql
-- pub_hours分桶及权重计算
CASE
    WHEN pub_hours < 0.5 THEN 4.0
    WHEN pub_hours < 2.0 THEN 2.0
    WHEN pub_hours < 24.0 THEN 1.0
    ELSE 0.6
END AS fresh_weight
```

权重曲线呈现"发布越新、权重越高"的单调递减趋势，与业务直觉一致：越新的帖子越需要被模型正确排序以获得公平的曝光机会。

#### 4.2 模型侧加权实现

在训练过程中，将`fresh_weight`作为样本级Loss权重传入模型：

```python
# 在loss计算时乘以样本权重
base_loss = bce_loss(logits, labels)  # 标准BCE损失
weighted_loss = base_loss * fresh_weight.unsqueeze(-1)  # 样本级加权
total_loss = weighted_loss.mean()  # 取mean保证scale一致
```

#### 4.3 多版本权重策略对比实验

| 方案           | 权重分布                     | 适用场景       |
| -------------- | ---------------------------- | -------------- |
| tiered（默认） | 4.0/2.0/1.0/0.6              | 平衡覆盖与聚焦 |
| binary_2x_5h   | \<5h→2×, ≥5h→1×              | 保守策略       |
| binary_3x_2h   | \<2h→3×, ≥2h→1×              | 激进策略       |
| binary_5x_1h   | \<1h→5×, ≥1h→1×              | 极端激进       |
| tiered_v2      | \<0.5h→4×, 0.5-2h→2×, ≥2h→1× | 精细分层       |

### 实施例五：组合特征`pub_hours × cate/price/brand`

#### 5.1 SQL预计算

在数据管道中，将`pub_hours`按5个业务桶分箱后，与品类/价格/品牌拼接：

```sql
-- 组合特征预计算示例
CONCAT_WS('_',
    CASE
        WHEN pub_hours < 1 THEN 'bucket_0_lt1h'
        WHEN pub_hours < 6 THEN 'bucket_1_1to6h'
        WHEN pub_hours < 24 THEN 'bucket_2_6to24h'
        WHEN pub_hours < 72 THEN 'bucket_3_24to72h'
        ELSE 'bucket_4_gte72h'
    END,
    cate_id_path,           -- 如 "19#731#1732"
    '__X__'
) AS phour_x_cate
```

#### 5.2 零碰撞哈希（ZCH）机制

对于预计算的组合特征键，在线推理时可能遇到训练期间未出现的组合（unseen key）。本发明采用零碰撞哈希（Zero Collision Hash，ZCH）机制进行兜底处理：

- **ZCH Size**：配置hash bucket池大小（如1,000,000），为所有item分配独立的hash位置
- **淘汰策略**：支持LFU（最少使用优先）、LRU（最近最少使用优先）或Distance-LFU策略，定期淘汰低频item
- **动态阈值过滤**：通过可配置的阈值过滤函数（如`dynamic_threshold_filter(x, 3.0)`），对访问频率低于阈值的item进行特殊处理，避免冷门item的embedding污染热门item的表示

```protobuf
id_feature {
    feature_name: "phour_x_cate"
    expression: "item:phour_x_cate"
    embedding_dim: 24
    zch {
        zch_size: 1000000
        eviction_interval: 2
        lfu {}
        threshold_filtering_func: "lambda x: dynamic_threshold_filter(x, 3.0)"
    }
}
```

### 实施例六：新帖样本Up-sample

在SQL训练样本管道中，对新帖样本进行复制up-sample：

```sql
-- up-sample SQL
SELECT * FROM base WHERE is_new_item = 0
UNION ALL
SELECT * FROM base WHERE is_new_item = 1
UNION ALL
SELECT * FROM base WHERE is_new_item = 1   -- 复制一份
```

效果：新帖训练占比从约17%提升至约29%，梯度对新帖的关注度约提升2倍。

风险：新帖样本重复可能导致过拟合，需通过AB测试验证线上效果。

## 摘要

本发明公开了一种面向电商导购场景的商品帖子智能分发方法及系统，属于电子商务推荐技术领域。该方法包括：获取包含用户行为特征、商品属性特征、发布时间特征及标题语义向量的训练样本；将样本输入多任务排序模型，基于发布时间计算样本级Loss权重进行加权训练；构建行为向量与标题向量的双向InfoNCE对比学习目标，将标题语义向量隔离于独立特征组以避免污染排序决策，并通过残差适配器优化语义对齐；在SQL数据管道中将发布时间与品类/价格/品牌组合并通过零碰撞哈希机制处理在线unseen组合；对训练数据中的新帖样本进行过采样以提升梯度贡献。本发明有效解决了新帖冷启动分发不足的问题，提升了新帖的曝光UV占比和UVCTR，同时避免了引入语义特征导致的品类跳跃问题。
